# ssquantdata 0.1.4 使用说明

[PyPI 0.1.4](https://pypi.org/project/ssquantdata/0.1.4/) 于 2026-10-22 发布。历史查询接口保持兼容，主要增加可核验的 WS 续鉴权与断线补齐能力。

## 安装

在运行 SSQuant 的同一个 Python 环境中执行：

```bash
python -m pip install --upgrade "ssquantdata[async,full]==0.1.4"
python -c "import ssquantdata; print(ssquantdata.__version__)"
```

`async` 用于异步 WS，`full` 用于 pandas/Parquet 物化。只使用同步 HTTP/WS 时可安装 `ssquantdata==0.1.4`。框架本体仍从 [SSQuant 源码仓库](https://github.com/songshuquant/ssquant) 安装；框架最新 main 已包含恢复期间暂停策略的配套修改。

## 与 0.1.3 的区别

| 项目 | 0.1.3 | 0.1.4 |
| --- | --- | --- |
| HTTP 登录和自动续期 | 支持 | 保持 |
| 原始历史字段和周期参数 | 支持 | 保持兼容 |
| WS 到期/短暂断线 | 明确停止 | 配套服务端支持时换令牌重连、按原序号补发 |
| 补发完整性 | 不提供保证 | 全部频道通过序号与完成栅栏核验后交付 |
| 无法核验的缺口 | 停止 | 仍停止 |

**仅安装新版还不能使当前生产具备自动补齐。** 服务端必须在 welcome 中声明 `resume_kline_v1`；配套服务端候选尚未部署。旧服务端继续采用明确停止规则。

## 补齐期间怎样处理

SDK 用同一个 TokenManager 的新令牌建立新连接，保留原 `stream_id` 和各频道序号。补发期间 `stream.recovering=True`，原消息保留原字段、序号和 `bar_revision`；核验完成后交付 `RecoveryEvent.cursors`。

框架在恢复期间暂停行情驱动的策略回调，先更新订阅缓存，之后等待新的实时触发再继续；不把补发的历史信号用于补做交易。历史快照和 `snapshot_seq` 不构成连续性证明。

重连次数、缓冲和恢复期限有界。服务重启、缺少消息、保留范围不足、溢出、鉴权拒绝或配额/连接政策拒绝，均可能使实时流明确停止，不承诺任意长断线都能恢复。

## 数据范围与验证边界

- 标准周期 `1M/5M/15M/30M/1H/1D` 及周线、自定义周期的实际可用性由服务端决定。
- 月线参数能被 SDK 接受，但 2026-10-21 生产月线请求返回 500，月线尚未通过验收；不要反复尝试 `1Y/1MON/1MO` 等别名。
- 未知成交额、订单流等字段仍保留未知；真实零保持零。日线在交易日结束前属于形成中。
- 当前生产不提供 Tick 实时推送，本次没有新增该功能。
- 发行包已从 PyPI 正常安装，230 项 SDK 测试通过，安装后的 21 个模块与发布源码一致。这些测试不能代替服务端部署后的真实令牌到期、自然断线及用户策略验收。
